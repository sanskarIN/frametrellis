# v1.3.0 candidate — manual editor and export smoke tests

> **Checklist, not a passing test report.** Run this against the exact frozen
> release-candidate commit. FrameTrellis v1.3.0 is not yet published.

This complements [the automated suite](../testing.md) and the
[release candidate acceptance matrix](../releases/v1.3.0-plan.md).
Capture the git SHA, build preset, operating system/architecture, Qt/MLT/FFmpeg
versions, `frametrellis.log`, pass/fail result and sample-output checksums.

## Media and project fixture

Prepare a **temporary directory** containing files you own, not the original
source assets you want to keep. Include:

- An H.264/AAC MP4 with motion, sound, and a changing colour in each second.
- A WAV or FLAC sound clip and a PNG still image, both with recognisable content.
- A copy of one media file with a Unicode basename, and a separate nested folder
  with spaces in its name.
- Enough footage to check trim handles, adjacent transitions and gaps.
- A saved `.ftproj` project created with the v1.2.2 editor, for backward
  compatibility testing. Keep an untouched copy for byte comparison.

## Editing path

1. Start the editor from the release candidate package or verified build.
   Import video, audio and image sources. Confirm media counts, thumbnails
   and audio waveforms. Re-import the same file through a relative-path
   alias: the media bin must not create a duplicate entry.
2. Add at least two video tracks and one audio track. Place clips on
   both video tracks, including intentional gaps. Confirm the higher video
   layer composites over the lower one.
3. Move, trim and split clips, then undo and redo each operation. Exercise
   snapping, transition creation/removal and clip adjustment reset.
   Confirm the preview and export results reflect the saved timeline.
4. Mute one audio clip, apply a fade to another, and verify the mix in
   playback and the final rendered file. Lock a track and attempt a move
   that should fail; there must be no partial move or undo-history entry.
5. Create a raster title from the dialog. Confirm it is placed on an
   unlocked video track and is composited above footage after export.
   Check behavior when all video tracks are locked.
6. Save, close and reopen the project. Confirm clip order, positions,
   audio mix and adjustments are unchanged. Open the older v1.2.2 project
   copy and verify it loads without migration or lost media references.
7. Move the project folder and its media together, reopen, and verify
   relative references. Test one missing source, then relink it to the
   proper file. Verify a relink collision with an already-used file is
   explicitly rejected.

## Rendering and safety path

1. Run the read-only project inspection:
   ```sh
   frametrellis-render --inspect-project --project smoke.ftproj
   ```
   Verify that the `@ft` JSON event reports counts consistent with the
   timeline, and does not disclose the full source paths.
2. Export a short MP4 with audio to a **different, empty destination**.
   Inspect the result with `ffprobe` (part of FFmpeg):
   ```sh
   ffprobe -v error -show_entries format=duration -show_entries stream=codec_name,width,height,r_frame_rate -of json smoke-export.mp4
   ```
   Check video dimensions and FPS, AAC audio where enabled, decoded picture,
   title overlay and correct duration. Verify both draft/fast and quality
   presets if they are available in the integrated build.
3. Start and cancel an export and ensure the original destination file,
   project file and source clips remain unchanged. Retry to the same
   destination and verify atomic replacement behavior.
4. Attempt an export whose destination is the **loaded project** in the
   temporary fixture, including a project document named with an `.mp4`
   extension. It must be rejected without changing that file. The test
   fixture is disposable; never perform this check on an irreplaceable project.
5. Run export and project inspection with Unicode and space-containing
   paths. Confirm the helper returns valid machine-readable status lines.

## Installer and documentation checks

- On clean Windows Server 2022, Windows Server 2025 and Windows 11 ARM64
  x64 emulation runners, inspect verifier results and preserved artifacts
  (installer, portable ZIP, GUI screenshot and logs). If any runner fails,
  investigate instead of relying only on a later retry.
- Open the website with JavaScript disabled, navigate the docs and use code
  blocks manually. With JavaScript enabled, test guide search, heading
  links and copy buttons using keyboard focus.
- Verify checksum files, SPDX SBOM, third-party source archive, installer
  and ZIP names all correspond to **the same target version and commit**.
- Confirm [draft notes](../releases/v1.3.0.md) contain only integrated
  changes and accurately disclose unsupported platforms and formats.
