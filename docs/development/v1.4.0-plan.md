# FrameTrellis v1.4.0 — post-v1.3.0 development plan

> **Planning only. Not released.** The latest published release is v1.2.2
> (23 October 2026). v1.3.0 is still in development. This plan proposes
> the *following* milestone and neither creates nor authorizes a tag,
> prerelease, or stable GitHub release.

## Theme: review, handoff and large-project workflows

After the core editing, data-safety and navigation work proposed for v1.3.0,
v1.4.0 should reduce the amount of manual checking needed to hand an edit to
another person or resume a large project.

### Proposed priority and scope

| Priority | Workstream | Initial deliverable | Gate |
|---|---|---|---|
| P0 | **Media audit** | Export a local, read-only JSON inventory with media paths, statuses and clip-use counts | Missing/changed-file regression tests, safe destinations, Windows/Linux GUI checks |
| P1 | **Review annotations** | Research and design persistent timeline markers with notes, sorted frame positions and undo/redo | Project-format backward compatibility, bounds and migration tests before UI |
| P1 | **Project portability** | Report external/offline references and create a deterministic relocation checklist | No silent file moves, copies or overwrites |
| P1 | **Media-heavy timeline** | Profile thumbnail and waveform memory/cancellation with real test fixtures | Measured performance change; no regressed preview or exports |
| P2 | **Review handoff** | Machine-readable project/clip summary options; format documented and versioned | Stable schema, sanitized untrusted fields and privacy notice |
| P2 | **Audio workflow** | Evaluate non-destructive audio metering improvements | Tested with generated tones and real audio exports |

Scope is deliberately **smaller than a fully featured NLE**. Subtitle editing,
keyframed filters, proxies, multi-cam, GPU acceleration and alternative export
containers need their own architecture/performance gates, and should not be
promised merely because they appear in the long-term roadmap.

## Phased implementation

**Phase A — data model and audits.** Build read-only project/media audit APIs
without changing the `.ftproj` version or touching source files. Define an
explicit JSON schema version; include missing, changed and unused media and
clip usage counts. Prevent output paths from replacing project/source media.

**Phase B — review annotations.** Design marker semantics separately:
unique ID, integer frame position, label, optional note and deterministic
ordering. Decide whether markers are project-level or timeline-level before
serializing them. Verify old saved projects can still be loaded, then add
undo/redo model commands and GUI controls. Do not ship a session-only
feature masquerading as persistent annotations.

**Phase C — scale and portability.** Profile actual long timelines with
generated fixtures; reduce memory or redundant IO only when measurements
justify complexity. Evaluate privacy-preserving relocation manifests.

**Phase D — candidate freeze.** Integrate feature PRs only after v1.3.0
stabilization, resolve QML controller/menu collisions, and run whole-product
regression tests with the combined head.

## Acceptance criteria

- [ ] v1.3.0 stable status and integration baseline are verified first.
- [ ] Relevant Linux GCC/ASan+UBSan and Windows MSYS2 GUI/unit/integration
      checks pass on the combined head.
- [ ] Windows portable ZIP/installer verification remains green, with
      website links and release artifacts checked independently.
- [ ] Existing v1.2.x and v1.3.x project files open and save without
      migration loss or unexpected new required fields.
- [ ] New reports do **not** modify project dirty/undo state, touch source
      files or overwrite referenced media; paths are recognized as private.
- [ ] All read-only reports have explicit schema versions and unit/GUI tests
      for missing files, modified files, empty projects and Unicode paths.
- [ ] Any future marker editing is undoable, bounded, persisted and
      backward-compatible; transitions, titles and clip timing remain intact.
- [ ] Full import → preview → multi-track edit → undo/redo → save → reopen →
      export test passes with actual generated media and audio.
- [ ] Changelog and user-facing website distinguish merged code from
      unreleased PRs and stable downloadable features.
- [ ] **Publication requires a new, separate explicit user instruction.**
      Do not tag, prerelease or publish from this plan.

## Non-goals

No unverified MLT parallel frame rendering (previously corrupted audio),
no automatic source-media relocation, no platform packages without clean
runner verification, and no changes to the WinGet publication process
unless independently approved.
