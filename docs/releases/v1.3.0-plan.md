## Integration order

1. **Complete:** integrated #71 after all eleven PR-head CI and clean Windows
   checks passed; the old conflicting #31 and #32 were closed as superseded.
2. Record any further confirmed P0 failures with minimal regression cases and
   fix them in focused PRs before freezing the candidate.
3. Freeze feature scope. Defer unresolved UI conflicts (including #70) to a
   later release unless they are proven essential and revalidated.
4. Freeze a `main` SHA, then run the exact release-candidate acceptance suite
   below **again on that integrated commit**.
5. Review [draft release notes](v1.3.0.md) and match each claim against the
   frozen commit; remove any unverified or deferred feature.

## Candidate acceptance matrix

| Gate | Verification and pass criteria |
|---|---|
| Linux build | CI: GCC debug, warnings as errors; all applicable CTest unit, integration and GUI tests pass |
| Sanitizers | CI: AddressSanitizer and UBSan; no new crash, race symptom or flaky failure accepted |
| Windows development | CI: MSYS2 UCRT64 editor and renderer build and tests pass |
| Windows redistribution | Windows packages workflow builds installer, ZIP, SBOM and licenses; clean-machine checks pass on Windows Server 2022, 2025 and Windows 11 ARM64 (x64 emulation) |
| Render engine | Container image build and self-test pass; MP4 picture/audio dimensions/duration confirmed from generated fixtures |
| Source data integrity | Save/Save As, title generation, snapshots and render output cannot replace referenced media or the loaded project; failed operations leave previous files intact |
| Edit correctness | Split, duplicate, trim, move, ripple-delete, multi-selection, undo and redo preserve timeline invariants; locked/colliding edits fail atomically |
| Recovery/compatibility | Save/reopen older v1 projects; relative/moved media paths; missing, relinked and externally modified sources; autosave/recovery |
| GUI | Modal-safe shortcuts, no conflicting bindings, Qt QML warnings, common screen sizes, navigation and copy/paste paths |
| Deployment/docs | Website and internal links pass; release assets have SHA256 checksums and SPDX SBOM; docs disclose known limitations |
| Version/notes | Exactly one target version after **approved** bump; package names match, release notes contain only integrated behavior and no draft flags |
| Publication | Separate explicit maintainer instruction **required** to tag, publish a GitHub release or prerelease |

Always confirm **all checks on the frozen integrated SHA**, not only on PR heads.
If main CI is cancelled by a newer merge, the newest complete run must be used.

### Branch protection: future hardening remains

The repository's active `main` ruleset (ID `25689246`) requires pull
requests and blocks non-fast-forward updates, but its required-status-check
list was **empty** during the pre-release audit. The v1.3.0 dispatcher
checked integrated CI and Windows packages independently before tagging.
A repository administrator should configure explicit required CI/package
checks for all **future** pull requests; the presence of green workflows
alone is not equivalent to enforcement. See
[main branch protection](../development/main-branch-protection.md).

For a reproducible end-to-end manual QA session, use the
[v1.3.0 smoke-test checklist](../development/v1.3.0-smoke-checks.md)
and record each result against the exact release-candidate SHA.

## Local verification examples

Configure, build and run tests in supported environments as documented in
[Building](../development/building.md) and [Testing](../testing.md):

```sh
cmake --preset linux-debug
cmake --build --preset linux-debug
ctest --preset linux-debug --output-on-failure
```

```sh
cmake --preset linux-asan
cmake --build --preset linux-asan
ctest --preset linux-asan --output-on-failure
```

From Windows **MSYS2 UCRT64**:

```sh
cmake --preset windows-msys2
cmake --build --preset windows-msys2
ctest --preset windows-msys2 --output-on-failure
```

Inspect the CI and Windows verification artifacts for the candidate SHA. Do not
take a green CI badge from another commit as proof that the candidate is ready.
