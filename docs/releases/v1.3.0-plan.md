- Merged to protected `main` (after green branch checks): **#19**
  renderer helper-protocol bounds, **#22** extreme signed-timecode safety,
  and **#23** protection against saving a project over referenced source

- All remaining candidate PRs in the table are still subject to review,
  conflict resolution and post-integration tests. No v1.3.0 tag exists.

## Integration approach

1. **Stabilize existing PRs first.** Fix failures on the actual branch HEAD:
   formatting, GCC/MinGW warnings-as-errors, GUI test failures, sanitizer
   regressions, Windows packaging, and website checks. Queued is not passing.
2. **Merge isolated fixes before overlapping QML features**, reviewing actual
   file-level and behavior conflicts. Rebase/update each remaining PR against
   `main` after integrating any PR that touches the same files.
3. **Verify edit-history correctness**: all project-changing actions must undo
   and redo exactly; invalid/locked/overlapping edits must not leave partial
   changes or create inconsistent command history.
4. **Verify source safety**: no project save, snapshot or export may overwrite
   source media; project relinks and moved-folder references remain valid.
5. **Regression test the combined product**, not just individual branch builds:
   import → preview → timeline edits → undo/redo → save → reopen → export.
6. **Freeze scope**: any optional P2 features with failing checks or unresolved
   conflicts move to a later minor release, not into an unverified v1.3.0.

## Release candidate acceptance criteria

All items must be checked against **the integrated commit intended for release**,
not successful CI from older feature-branch heads:

- [ ] `main` remains protected, no force-push, all integrated PRs reviewed.
- [ ] Linux GCC debug warnings-as-errors tests pass.
- [ ] Linux AddressSanitizer/UndefinedBehaviorSanitizer unit and integration
      tests pass.
- [ ] Windows MSYS2 UCRT64 editor and renderer build and tests pass.
- [ ] Full Qt GUI tests pass (mouse, QML dialogs, clipboard, keyboard actions).
- [ ] Windows installer and portable ZIP verify on Windows Server 2022 and
      Windows Server 2025, plus Windows 11 ARM64 under x64 emulation.
- [ ] Container image self-test passes; website docs and links pass.
- [ ] Review existing project-file compatibility: v1.2.2 project opens and
      saves correctly. If the format remains v1, this is explicitly documented.
- [ ] Export media verified: dimensions, duration, picture, AAC audio, and
      output replacement/cancellation behavior on a real generated-media test.
- [ ] Check Unicode paths, relinked/offline media, autosave recovery,
      no-upscale presets, generated title PNGs and multi-track transitions.
- [ ] All new menu shortcuts are unique, modal-safe, documented and exercised
      by GUI tests after feature integration.
- [ ] No known P0/P1 crash, data-loss or source-overwrite issue remains open.
- [ ] User guide, shortcut list, release notes, limitations and changelog
      match **only integrated features**.
- [ ] Official v1.3.0 release notes are reviewed and `CMakeLists.txt` version
      is changed **only on an explicitly approved release-preparation PR**.
- [ ] Maintainer gives a **separate, explicit instruction to publish**.
      Until then, do not create a stable tag, GitHub release, or a GitHub
      prerelease either.

## Versioning and scope boundaries

- Preserve project-format compatibility unless a version migration is
  designed, tested and approved separately.
- Do **not** reenable experimental MLT parallel frame rendering. Earlier
  configurations corrupted audio; faster encoding is not a justification
  for risking output integrity.
- A new WinGet submission or store listing is outside this milestone
  until independently accepted and verified.
- Editable vector titles, subtitles, proxy workflow, GPU encoding, keyframes,
  additional container formats, Linux/macOS packages and performance
  virtualization are not automatically included in v1.3.0.
- The open **v1.2.3 What's New** PR (#18) references another release series;
  update or defer it deliberately rather than shipping stale version labels.

## After integration, before publication

Once the integrated release candidate meets all gates, prepare
`docs/releases/v1.3.0.md` with **only verified merged changes**, update the
project version and run a nonpublishing release-workflow rehearsal if explicitly
authorized. Do not treat a nonpublishing rehearsal as permission to publish.
