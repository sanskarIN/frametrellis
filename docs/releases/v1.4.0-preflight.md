## Manual acceptance scenarios

Run the [v1.4 integrated editing matrix](../testing/v1.4-integrated-editing-acceptance.md),
particularly T01–T16, B01–B11, subtitle and delivery checks and the project
format/recovery matrix. In particular, check T15 (copy timecode report) and
the invalid-state save preservation test, in addition to generated media,
sound verification notes and failed-case logs.

On a clean Windows machine, exercise:
1. Install and launch the installer; independently extract and start the ZIP.
2. Import MP4/WAV/PNG, build a multi-track sequence, trim/move/split, save,
   close, reopen and inspect the actual monitor and audio playback.
3. Check title overlays, fades, volume/opacity/transform automation, subtitles
   and markers, then export and inspect a real MP4 with audio.
4. Export SRT, WebVTT, TXT, EDL, CSV and PNG assets; verify encodings,
   destinations and source-overwrite protection.
5. Verify a **copy** of a v1 project and representative newer v2–v6 project
   documents; do not destructively overwrite the originals.

Project format differences: v2 markers, v3 volume curves, v4 opacity,
v5 transforms and v6 subtitles. Older v1.3.1 binaries may reject projects
saved with newer features. Verify compatibility and warning behavior.

## Rehearsal and release decision

1. Merge reviewed v1.4.0 preparation PR(s) after their own checks pass.
2. Freeze main at SHA __________. Obtain **successful** complete main runs
   for CI, Windows packages and website, and confirm container self-test.
3. In Actions → Release → Run workflow, choose **main**, leave
   **publish=false**, and confirm success and retained release-notes,
   Windows package and checksum artifacts. This rehearsal must not
   create a tag or GitHub release.
4. Review actual Windows clean-runner logs, manual QA evidence and artifacts;
   fix problems, re-freeze the SHA and re-run the gates if required.
5. Only with explicit publication approval, create v1.4.0 on the verified
   commit or use the guarded publication workflow. Confirm the published
   assets, checksums, source archive, release notes and website links.

**Do not call v1.4.0 stable or provide installation links to it while this
document is in the pending state.** The repository's published stable
continues to be v1.3.1 until GitHub confirms otherwise.
