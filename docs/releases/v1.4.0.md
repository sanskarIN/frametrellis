# FrameTrellis 1.4.0 — Early access release notes

FrameTrellis 1.4 introduces workflow tools for review, interchange and precise
source editing. Initial packages should be treated as a **prerelease**, intended
for hands-on evaluation before a future stable 1.4.0 release. Stable 1.3.0
remains available for production use.

## What's new

- **Persistent review markers** ([PR #75](https://github.com/sanskarIN/frametrellis/pull/75)):
  create and edit named frame-accurate sequence markers, use ruler diamonds,
  jump to adjacent markers and snap edits to review points. Marker changes are
  undoable and saved in the project.
- **Chapter publishing** ([PR #76](https://github.com/sanskarIN/frametrellis/pull/76)):
  copy marker timestamps as video-description chapters or a frame-derived WebVTT
  chapter track. A marker at frame zero is required; invalid or ambiguous
  chapter boundaries are rejected without modifying the project.
- **CMX3600 picture EDL** ([PR #77](https://github.com/sanskarIN/frametrellis/pull/77)):
  copy validated source and record timecodes for cuts, with explicit black-gap
  events, source identifiers and 29.97 drop-frame labels. This is picture-only
  interchange, not full media or project export. Layered timelines, effects,
  fades, dissolves, stills and incompatible source rates must first be handled
  manually in an external conform workflow; unsupported layouts are rejected.
- **Clip slip editing** ([PR #79](https://github.com/sanskarIN/frametrellis/pull/79)):
  change the source in/out points of selected video or audio clips while their
  timeline position and duration remain fixed. Works across selected tracks as
  one undo step, preserving existing transitions and rejecting unavailable
  source handles or locked tracks. Use the Edit menu, keyboard shortcuts or
  Clip Inspector controls.
- **Media-bin interaction fix** ([PR #78](https://github.com/sanskarIN/frametrellis/pull/78)):
  avoid a Qt Quick GridView delegate reference error when selecting media.

## Important project-file compatibility change

The new marker-aware document writer uses **project format v2**. FrameTrellis
1.4 reads existing v1 projects; however **FrameTrellis 1.3.x and older cannot
read a project once it has been saved by 1.4**, even if no markers were added.
Before testing the prerelease, make a separate copy of each valuable `.ftproj`
project and its associated files. Do not overwrite the only copy of a project
you may need to reopen with 1.3.0. Source media itself is not modified.

## Export and platform limitations

- Video output remains MP4/H.264/AAC; markers are **not** burned into video.
- WebVTT and EDL actions copy text to your system clipboard. Paste into a
  UTF-8 `.vtt` or `.edl` file, as appropriate.
- EDL is cuts-only, single visible picture track and no audio conform.
- Slip editing does not apply to still-image clips.
- Windows x64 installer and portable ZIP are produced only if the tag-specific
  release pipeline passes clean-host Windows package verification.
- Linux and macOS builds remain source-build workflows, not official binary
  downloads for this prerelease. Windows packages are not code-signed.

## Verification boundary

Feature PRs passed Linux/Windows CI, sanitizers, formatting and package tests.
The **merged release candidate** must pass its own same-commit CI and packaging
gates; completion of a human desktop smoke test and external EDL import test
is recorded separately. See
[the v1.4 evaluation checklist](../development/v1.4.0-smoke-checks.md).
This note does not by itself establish that a GitHub prerelease or binaries
have been published.
