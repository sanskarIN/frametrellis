# FrameTrellis v1.5.0 — featured release scope and acceptance matrix (DRAFT)

**Status:** candidate planning only, **not approved for a stable release**. The latest
published stable remains [v1.4.0](https://github.com/sanskarIN/frametrellis/releases/tag/v1.4.0).

owner explicitly approves the completed feature scope and evidence.

This document separates *merged development work* from *proposed or still-reviewed
changes*. A merged PR is not a promise of hardware reliability; the release
[preflight checklist](v1.5.0-preflight.md) governs final acceptance.

## Still in development (do not advertise as stable)

The Unicode-safe project rename from [PR #28](https://github.com/sanskarIN/frametrellis/pull/28)
**was merged** into development `main` and belongs in the table above. It
still needs physical GUI and save/reopen acceptance on the frozen candidate.

Experimental packaging is not official Linux/macOS distribution: the separate
[macOS signed-versus-mounted inventory gate #247](https://github.com/sanskarIN/frametrellis/pull/247)
is under CI review, and no open development PR or successful package smoke
alone authorizes a v1.5.0 release.

[Closed, never-merged diagnostic PR #218](https://github.com/sanskarIN/frametrellis/pull/218)
rebuilt the exact pre-#210 source tree under a newer MSYS2 package environment.
Its three Windows hosts reproduced a packaged GUI timeout even without the new
ripple edit. The underlying missing SDL3 dynamic dependency was fixed in #219;
the synchronized V+A edit remains integrated.

Development `main` features still require integrated exact-commit verification
and physical Windows x64 listening, long export and project-reopen acceptance.
Merged does not mean v1.5.0 stable has shipped.

## Release-blocking quality matrix

- **Resolved packaging regression:** [#217](https://github.com/sanskarIN/frametrellis/issues/217)
  was fixed by [#219](https://github.com/sanskarIN/frametrellis/pull/219):
  the SDL2 compatibility runtime now includes its dynamically loaded SDL3
  dependency. All three clean-host GUI verifiers passed on the integrated
  packaging-fix SHA. Repeat the exact frozen-candidate checks before release;
  this does not resolve distinct crashes #175 or #185.
- **Native failures:** [#175](https://github.com/sanskarIN/frametrellis/issues/175)
  and [#185](https://github.com/sanskarIN/frametrellis/issues/185) need
  cause-backed fixes or an explicit, evidence-backed owner go/no-go decision.
  Synthetic/self-test success does not prove the real crash is gone.
- **Desktop workflow:** physical Windows x64 source and program monitors,
  independent audio output, multiclip timeline edits, captions/markers, save/reopen,
  auto-recovery and both installer/portable distribution.
- **Export correctness:** H.264/AAC with picture and audio; complete, selected
  and custom ranges; match/24/25/30000/1001/30/60 FPS; cancellation and output
  file integrity; repeated long real project renders and separate media probe.
- **Batch export correctness:** 2–3 UI delivery variants, one immutable
  project snapshot, verified dimensions/FPS/durations and source audio, distinct
  per-preset output paths, atomic no-overwrite publication even during races,
  valid progress and no further launches after cancellation or failure.
- **Project compatibility:** representative v1–v7 files, documented format
  transitions, saves/undo/redo, no changes to source media on disk.
- **Automated suites:** Linux GCC warnings-as-errors and clang-tidy, sanitizers,
  Windows MSYS2, Windows 2022/2025/11 ARM clean package verification,
  container renderer self-test and website, all at the *same frozen SHA*.
- **Publication gate:** owner approval, manual release preparation, independent
  SHA256SUMS/SBOM/source-archive verification, then owner-created stable release
  and independently verified five-asset attachment. No speculative publication.
