## Automated verification on the frozen SHA

- [ ] Linux GCC warnings-as-errors and complete unit/integration/GUI CTest.
- [ ] Linux x64: full native Qt Quick editor, audio and renderer pass the
      desktop-platforms workflow; verify staged `bin/frametrellis`,
      `bin/frametrellis-render`, desktop entry, icon and executable smoke.
      A Homebrew/Qt/MLT-dependent development tarball is **not** a portable
      AppImage/Flatpak. Before release require an independent clean-host
      packaged runtime, complete dependency/license audit, MP4 sound/FPS
      validation, and user-level install/uninstall/recovery.
- [ ] macOS Apple Silicon (arm64) and Intel (x64): full editor compile,
      unit/integration/GUI tests and standalone helper self-test on both native
      runner architectures. Verify the helper lives in the .app's
      Contents/MacOS folder and works after installation.
- [ ] macOS development DMGs on **both native Intel and Apple Silicon**:
      validate codesign on staged and read-only mounted applications, compare
      every mounted byte and symlink with the post-ad-hoc-signature staged
      inventory (PR candidate; cannot be checked off until the exact frozen
      release commit passes). A development DMG smoke is not proof of
      production signing, Gatekeeper acceptance or clean-Mac runtime support.
- [ ] macOS release artifact: bundle all Qt/QML, MLT/FFmpeg and SDL dylibs,
      MLT modules/data, fonts and required licensing information; test on
      **clean** Macs with no Homebrew installation. Confirm architecture,
      embedded dependency references (`otool -L`), valid signed/notarized
      delivery. Run `packaging/macos/verify-notarized-candidate.sh` against
      the exact frozen DMG on **native Intel and native Apple Silicon** for
      SHA-256, stapled ticket, Developer ID and quarantined Gatekeeper
      acceptance. Run a separate real Finder GUI launch, audible playback and
      long MP4 export; the automated signature verifier does not replace
      physical runtime QA. Development .app archives that still depend on
      Homebrew **must not** be published as stable downloadable installers.
- [ ] Waveform decoding must reject malformed, zero, negative and very
      large media durations **before** converting to `size_t`/`int` or opening
      an MLT decoder. Run `tst_waveform_duration` in the native test suites;
      waveform cache and preview behavior for valid files remain unchanged.
- [ ] AddressSanitizer + UndefinedBehaviorSanitizer.
- [ ] Windows MSYS2 compilation and full test suite.
- [ ] Windows portable ZIP and installer on clean Windows Server 2022/2025;
      require three independent default-backend GUI launches on each host and
      fail any three-minute screenshot/GUI shutdown timeout (see #217).
- [ ] Render real short synthetic MP4s using the **packaged**
      CLI at Match, 24, 25, 30000/1001, 30 and 60 FPS on every clean
      Windows host. The helper verifies output stream rate internally, and
      package verification independently checks output existence and MP4
      container headers; the separate packaged CLI build checks exact NTSC
      FPS and custom even output width with independent FFprobe.
      Require strict --refuse-existing-output SHA256 preservation and
      independently probe and listen to long real-media exports before release.
- [ ] After SDL2 package migration, independently inspect the ZIP for
      `SDL2.dll` plus `SDL3.dll` when `sdl2-compat` is the installed provider;
      check the SDL3 license/SBOM record and restored GUI launches. A successful

      [#219](https://github.com/sanskarIN/frametrellis/pull/219).
- [ ] Windows 11 ARM x64 emulation: repeated strict default launches
      plus independent software-rendering and SDL dummy-audio diagnostics;
      no retry or alternative backend masks a failed default launch.
- [ ] Independent FFprobe and FFmpeg decode of freshly generated synthetic MP4
      from **the extracted packaged Linux AppImage helper and isolated clean
      Ubuntu container**, the read-only mounted DMG renderer on both native
      Mac architectures, and the Windows package-build CI:
      exact 25 fps, 640x360, H.264/MPEG-4 video, AAC audio and non-silent
      decoded audio samples. See `packaging/verify_export_media.py`. These
      development-bundle checks do not establish production notarization,
      legal source completeness, physical audio playback or long export QA.
- [ ] Renderer/container self-test and docs/website checks.
- [ ] Independent archive verifier confirms **both**
      `frametrellis.exe` and `frametrellis-render.exe` are adjacent
