# FrameTrellis v1.5.0 — Windows binaries with Linux/macOS source-build support

> **ALTERNATIVE DISTRIBUTION PLAN — NOT APPROVED FOR RELEASE.**
> Nothing here creates a GitHub tag or releases any binaries. The existing
> [full 14-asset three-platform binary plan](v1.5.0-owner-release-runbook.md)
> remains available as a separate, stricter option. The owner must choose
> **exactly one** publication scope after all evidence is complete.

## The precise platform promise

| Platform | What the v1.5.0 source-build option would deliver |
| --- | --- |
| Windows 10 1809+/Windows 11 x64 | Official portable ZIP and installer (not code signed) |
| Windows 11 ARM64 | Same x64 ZIP and installer under x64 emulation (subject to crash acceptance) |
| Linux x86_64 | **Supported to build from source** with documented Qt/MLT/FFmpeg/SDL dependencies; **no official AppImage** |
| macOS 15+ Apple Silicon arm64 | **Supported to build from source** with Homebrew dependencies; **no notarized DMG** |
| macOS 15+ Intel x86_64 | **Supported to build from source** with Homebrew dependencies; **no notarized DMG** |

This route removes **portable Linux/macOS package delivery** from the v1.5.0
candidate requirements, not source-level platform tests or truthful claims.
It must not be called a three-platform *installer* release.

## Steps for the repository owner — only after all gates pass

1. Open [GitHub Actions](https://github.com/sanskarIN/frametrellis/actions/workflows/release.yml),
   select **Prepare manual release**, choose `main`, and select **Run workflow**.
   Record the exact main SHA and the successful workflow run ID.
   Its candidate artifact is called `manual-release-assets`; inside are
   `release/` (the five files) and `release-notes.md`.
2. Download the complete artifact and independently verify, with a checkout
   at the same frozen SHA:
   ```bash
   python3 packaging/verify_release_assets.py --version 1.5.0 --directory ./release
   cd release && sha256sum --check SHA256SUMS.txt
   ```
   The verification is archive/integrity evidence, not native Windows audio QA.
3. After separate owner approval, visit
   [Draft a new release](https://github.com/sanskarIN/frametrellis/releases/new).
   Create the tag `v1.5.0` **only from the exact frozen tested `main` commit**;
   refuse if `main` changed. Use title:
   `FrameTrellis 1.5.0 — Featured Release`.
4. Use final, accurate contents of `docs/releases/v1.5.0.md` as the
   description. Explain that macOS and Linux **source builds are supported**,
   while official downloads are **Windows only**. Append this exact line,
   on its own, **only after separate approval**:

   ```text
   FrameTrellis-1.5.0-SOURCE-BUILD-OWNER-APPROVED
   ```

   Do **not** also add `FrameTrellis-1.5.0-OWNER-APPROVED`:
   that is the distinct **14-file** distribution's marker.
5. Keep **Pre-release** unchecked, choose **Latest**, and leave the asset
   attachment area **empty**. Select **Publish release** only when fully
   authorized. Publishing immediately makes the release public, **before**
   automatic asset attachment succeeds.
6. Watch **Attach approved v1.5.0 Windows assets (source builds on Linux and
   macOS)**. It requires the exact approval marker, same SHA, matching
   version/final notes, exact CI and native Linux/macOS source-build passes,
   fresh verified Windows candidate and **empty** release asset list before
   uploading **exactly five** files. It compares public GitHub SHA-256
   digests, sizes and uploaded state to the offline candidate. The separate
   14-file uploader must be **skipped**, not run simultaneously.
7. Independently download all five assets and compare SHA-256. Verify Windows
   install, clean launch, real audio and MP4 render, the source/build links,
   and the published site download URLs. Announce **only after** complete
   assets and links are verified.

**Failure boundary:** Publication may be visible without completed assets. An
uploader failure or partial asset set is **not a successful release**. Stop
promotion, inspect the release and CI run; do not replace files with those
from a different SHA or manually mix two upload routes.
