# FrameTrellis v1.5.1 — owner release candidate and publication runbook

**Candidate preparation is allowed; publication is not approved by this page.**
The latest public release is still
[v1.5.0](https://github.com/sanskarIN/frametrellis/releases/tag/v1.5.0).
The v1.5.1 tag must not be created, and the stable release must not be
published, until the owner separately authorizes both from the verified,
unchanged 40-character SHA. Consult [issue #301](https://github.com/sanskarIN/frametrellis/issues/301)
for live acceptance status.

## Intended platform scope

- Windows 10 1809+/11 **x64**: unsigned installer and portable ZIP.
- Windows 11 ARM: x64 build through emulation, with unresolved intermittent
  native-startup-risk [#185](https://github.com/sanskarIN/frametrellis/issues/185).
- Linux x86_64 and macOS 15+ Intel/Apple Silicon: **source builds**, requiring
  appropriate native Qt, MLT, FFmpeg and (if available) audio dependencies.
- Experimental Linux AppImages or unnotarized macOS DMGs are not official
  downloads for this release. Do not claim they are.

## Required quality gate — must be evidence, not assumptions

- [ ] Freeze protected `main` to a precise 40-character SHA that contains
  CMake version 1.5.1 and these candidate notes. Every later merge resets
  release evidence and requires new checks.
- [ ] Verify passing CI, packaging checks, Windows packages and clean-host
  verification on **windows-2022**, **windows-2025**, **windows-11-arm**,
  Linux x64 GUI/engine, native macOS Intel/arm64 and website on that **same SHA**.
- [ ] Read the successful Windows package job's independently decoded video
  and non-silent AAC verification. It exercises match, 24, 25, 30000/1001,
  30 and 60 FPS, custom dimensions and a roughly one-minute multitrack
  synthetic NTSC output. **Synthetic CI is not real user's long-export QA.**
- [ ] On physical Windows x64, launch both an extracted portable ZIP and
  installer from the **candidate SHA** and record the exact
  Help → About source revision and package version.
- [ ] Confirm screenshot-reported Export dialog repair: full preset text,
  output path, Quality, Speed, Scaling, Audio, FPS and batch controls aligned
  at normal size and on a smaller display. Switch each timeline range mode;
  reach the Export single MP4 and Export N variants actions through scrolling.
- [ ] With copies of existing media/project, confirm real preview audio,
  a 30-minute-or-longer MP4 H.264/AAC export, sample picture/audio sync,
  changed export FPS, cancellation/retry, and preserved existing destination.
  Capture redacted memory/disk/error evidence if any process terminates.
- [ ] Check import → edit → save → close → reopen, autosave recovery and
  opening a **backup** of a v1.5.0 project. Do not test migration destructively.
- [ ] Record explicit go/no-go treatment for
  [#175](https://github.com/sanskarIN/frametrellis/issues/175) (user-observed
  editor/render native crash) and
  [#185](https://github.com/sanskarIN/frametrellis/issues/185) (intermittent
  ARM launch). A passing CI run does not prove native root-cause resolution.
- [ ] Confirm version-specific release notes match the actual frozen SHA.
- [ ] Obtain **separate explicit owner permission for public stable publication**.

## Offline candidate artifacts (do not create a GitHub Release)

1. Choose the frozen `main` SHA after the version PR merges. Open
   [Prepare manual release](https://github.com/sanskarIN/frametrellis/actions/workflows/release.yml).
   Its eligible push automatically runs, or the owner may use **Run workflow**
   with `main`. This job does **not** create or publish a release.
2. Require a **successful** run whose `head_sha` exactly equals the current
   frozen `main`, and download its unexpired `manual-release-assets` artifact.
   It contains `release-notes.md` and `release/` with exactly five assets.
3. Verify an extracted download at that SHA:

   ```bash
   python3 packaging/verify_release_assets.py --version 1.5.1 --directory ./release
   cd release
   sha256sum --check SHA256SUMS.txt
   ```

   On Windows, compare SHA-256 using PowerShell
   `Get-FileHash .\\FrameTrellis-1.5.1-windows-x64-setup.exe`.
   If a file, checksum, ZIP member, SPDX version, third-party-source TAR or
   requested package version fails, **do not proceed**.

Expected files:

| File | Purpose |
| --- | --- |
| `FrameTrellis-1.5.1-windows-x64-setup.exe` | Unsigned Windows x64 installer |
| `FrameTrellis-1.5.1-windows-x64.zip` | Portable Windows x64 editor + render helper |
| `FrameTrellis-1.5.1-windows-x64.spdx.json` | Windows package SPDX SBOM |
| `FrameTrellis-1.5.1-windows-x64-third-party-sources.tar` | Corresponding source packages |
| `SHA256SUMS.txt` | Checksums for the four payloads |

## Publication — only after owner authorizes the exact candidate

1. Double-check the public-release tag `v1.5.1` does not already exist.
   Freeze `main`; compare its full SHA against the passing CI, native desktop
   and offline preparation runs. **Never create a tag pointing elsewhere.**
2. Open [New GitHub Release](https://github.com/sanskarIN/frametrellis/releases/new)
   while signed in as the owner. Create tag `v1.5.1` from the **same SHA**;
   title: `FrameTrellis 1.5.1 — Maintenance Release`.
3. Use the complete, verified `release-notes.md`. Only after separate
   owner authorization, append the exact single-line approval marker
   `FrameTrellis-1.5.1-SOURCE-BUILD-OWNER-APPROVED`.
   Do not use the conflicting 14-file marker.
4. Set **Latest**, leave **Pre-release** unchecked, and keep the manual asset
   attachment area **empty**. **Publish release** only after explicit approval.
   The release becomes visible immediately, before the uploader finishes.
5. Watch
   [Attach approved v1.5.1 Windows assets](https://github.com/sanskarIN/frametrellis/actions/workflows/release-assets-v151-source.yml).
   It requires exact main/tag SHA, exact marker/version, current green CI,
   a successful same-SHA preparation and a verified empty release asset list.
   The incompatible legacy uploader must not run.
6. After attachment, independently check all five public file names,
   ready states, sizes, SHA-256 values, actual installer/portable downloads
   and website links. Only then announce release completion.

**Failure boundary:** Never replace v1.5.0 files, bypass a failing gate, upload
unverified binaries, or mix archives from different commits. If the uploader
fails after publication, the GitHub Release may remain visible **without**
a complete asset set; treat that as incomplete, do not announce it, and
investigate before any recovery.
