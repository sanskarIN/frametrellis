# FrameTrellis v1.5.2 — owner candidate and release runbook

**Current state: candidate engineering only; NOT RELEASE READY and NOT PUBLISHED.**
The latest verified public stable is [v1.5.1](https://github.com/sanskarIN/frametrellis/releases/tag/v1.5.1).
The [live release tracker #317](https://github.com/sanskarIN/frametrellis/issues/317)
and [preflight checklist](v1.5.2-preflight.md) control the release decision.
No target date, green PR or version bump grants permission to publish.

## What v1.5.2 is allowed to distribute

- **Windows 10/11 x64:** unsigned installer and portable ZIP containing the editor
  and its render helper, plus SPDX SBOM, corresponding third-party sources
  and a SHA-256 manifest.
- **Linux x86_64 and macOS Intel/Apple Silicon:** documented source builds
  with matching Qt/MLT/FFmpeg dependencies.
- Windows 11 ARM uses the x64 build through emulation; the intermittent
  native startup failure in [#185](https://github.com/sanskarIN/frametrellis/issues/185)
  remains a release risk.
- Experimental AppImages and unsigned/unnotarized DMGs are **not** official
  production installers under this five-file distribution scope.

## Gate A — integration and one frozen source revision

- [ ] Integrate reviewed maintenance PRs only after their **own exact-head**
  required CI jobs pass. Resolve conflicts and rerun checks rather than
  relying on success from an earlier head.
- [ ] Merge the reviewed v1.5.2 project-version PR after the implementation
  scope is accepted. Confirm `project(FrameTrellis VERSION 1.5.2)` on
  protected `main`, and check the installer/ZIP report version 1.5.2.
- [ ] Remove the **CANDIDATE NOTES — NOT PUBLISHED** preamble from
  [v1.5.2 notes](v1.5.2.md) only through an explicitly reviewed final
  notes change. Cross-check every claimed feature against merged code.
- [ ] Freeze one **full 40-character SHA** of protected `main`. Record it
  in the release tracker. Every later merge invalidates the freeze and
  requires fresh combined CI/package/notes review.

## Gate B — same-SHA automated qualification

The following **must all succeed on that exact frozen main SHA**, not merely
on a PR head:

- [ ] [CI](https://github.com/sanskarIN/frametrellis/actions/workflows/ci.yml):
  formatting, packaging unit tests, Linux GCC/Qt GUI, ASan/UBSan and Windows MSYS2.
- [ ] [Windows packages](https://github.com/sanskarIN/frametrellis/actions/workflows/package-windows.yml):
  successful package build and **independent** verifier jobs on Windows 2022,
  Windows 2025 and Windows 11 ARM, including synthetic MP4 picture/audio checks.
- [ ] [Linux and macOS desktops](https://github.com/sanskarIN/frametrellis/actions/workflows/desktop-platforms.yml):
  native Linux GUI and native macOS x64/arm64 builds/install smoke tests.
- [ ] [Website](https://github.com/sanskarIN/frametrellis/actions/workflows/website.yml):
  documentation and published **v1.5.1** download links remain correct;
  do not advertise v1.5.2 assets before publication.

Use the run's **head SHA** and final **completed/success** result. Record
individual job IDs where necessary; a checked PR or a queued/pending run is
not proof that the frozen main candidate passed.

## Gate C — physical Windows hardware and native crash assessment

- [ ] Use both installer and portable assets from **the same candidate SHA**.
  Verify application About/source revision, cold and repeated real GPU launches,
  preview with real audio output, and save/reopen of backed-up v1.5.0/v1.5.1
  `.ftproj` projects.
- [ ] Perform **two 30+ minute real multitrack H.264/AAC exports**, independently
  validate duration, frame count, output resolution, AAC sound and synchronization,
  then reimport both. Test match, 24, 25, 30000/1001, 30 and 60 FPS.
- [ ] Exercise cancel/retry, existing destination preservation, disk pressure
  and no orphan partials. Keep original projects and media untouched.
- [ ] Record an evidence-based go/no-go for the observed Windows editor
  `0xC0000005` and renderer `0xC0000006`
  ([#175](https://github.com/sanskarIN/frametrellis/issues/175)).
  Synthetic protocol CI is **not** evidence of a native root-cause fix.
- [ ] Test real Windows 11 ARM GUI launches (default and diagnostic software
  renderer) and investigate any failure under [#185](https://github.com/sanskarIN/frametrellis/issues/185).
  Hosted CI non-reproduction is not proof of a cure.

Record actual machine, package SHA, export durations and private local evidence in
the [physical Windows worksheet](v1.5.2-physical-windows-qa.md). Do not
publish footage, crash dumps, usernames or private media paths by default.

## Gate D — produce and verify the **offline** five-file candidate

After Gates A–C and a complete notes review, use
[Prepare manual release](https://github.com/sanskarIN/frametrellis/actions/workflows/release.yml)
on protected `main`. This workflow **does not create a tag or public release**.
Its successful run must have `head_sha` identical to the frozen SHA.

Download the unexpired `manual-release-assets` artifact from **that exact run**.
It must contain the final `release-notes.md` plus `release/` with exactly:

| Expected filename | Description |
| --- | --- |
| `FrameTrellis-1.5.2-windows-x64-setup.exe` | Windows x64 installer |
| `FrameTrellis-1.5.2-windows-x64.zip` | Portable GUI and render helper |
| `FrameTrellis-1.5.2-windows-x64.spdx.json` | SPDX 2.3 package SBOM |
| `FrameTrellis-1.5.2-windows-x64-third-party-sources.tar` | Corresponding source archive |
| `SHA256SUMS.txt` | Digests of the four payloads |

From the matching source checkout, validate the extracted artifact:

```bash
python3 packaging/verify_release_assets.py --version 1.5.2 --directory ./release
(cd release && sha256sum --check SHA256SUMS.txt)
```

On Windows, compare the installer/portable digest with `Get-FileHash`.
The verifier checks archive paths, contents, manifest, version and package
structure; physical playback, hardware audio and long-video QA are separate.
Reject mixed-SHA, expired, missing, corrupt or unexpected files.

## Gate E — **separate** exact-SHA owner authorization and publication

Only after all previous gates pass, request explicit owner authorization for
**stable v1.5.2 at the exact frozen SHA**, the five-file scope and any
explicitly accepted remaining native risk. Do not infer authorization from
this document, development requests, CI or a version bump.

1. Confirm the public tag/release `v1.5.2` **does not already exist**.
   Confirm frozen protected `main` has not advanced and all release assets
   and notes are reviewed at that commit.
2. In [GitHub New Release](https://github.com/sanskarIN/frametrellis/releases/new),
   create `v1.5.2` from **that exact SHA**. Suggested title:
   `FrameTrellis 1.5.2 — Maintenance Release`.
3. Use the verified `release-notes.md` and append **only if separately
   authorized** this exact standalone marker line:
   `FrameTrellis-1.5.2-SOURCE-BUILD-OWNER-APPROVED`.
   Never reuse v1.5.0/v1.5.1 or the incompatible 14-file marker.
4. Leave **Pre-release** unchecked and public asset attachments **empty**.
   Publishing makes the release visible immediately even before automatic
   attachment finishes. Do not announce the release before final verification.
5. Review the
   [owner-gated v1.5.2 uploader](https://github.com/sanskarIN/frametrellis/actions/workflows/release-assets-v152-source.yml).
   It must independently confirm tag/main equality, source and marker,
   successful exact-SHA CI, authenticated offline preparation, zero existing
   assets, verified five-file contents and final uploaded SHA-256 digests.
6. Independently check all five public asset names, sizes, ready states,
   checksums and real installer/portable downloads. Verify the website still
   directs users only to a genuinely published release before announcement.

**Failure boundary:** A failed check blocks release. Do not skip native
hardware results, retag previous releases, overwrite public assets, mix
builds from different revisions or claim the uploader fixed an incomplete
public release. If publication begins but attachment fails, treat the
public page as **incomplete**, withhold announcement and investigate.
