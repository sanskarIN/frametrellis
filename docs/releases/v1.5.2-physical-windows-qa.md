# FrameTrellis v1.5.2 — physical Windows qualification worksheet

**Preparation only.** The proposed candidate is not yet tagged or published.
This worksheet supplements [v1.5.2-preflight.md](v1.5.2-preflight.md)
and [release tracker #317](https://github.com/sanskarIN/frametrellis/issues/317).
Hosted CI and experimental Windows/ARM emulation are not evidence that real
sound hardware, long media or a particular physical GPU works.

## Before the test

1. On a **physical Windows 10/11 x64** machine, obtain the candidate installer
   and portable ZIP from one *frozen reviewed main SHA*. Check both show the
   same source revision in **Help → About**. Do not test with a mixture of
   released 1.5.1 files and newer development executables.
2. Make a **copy** of a project containing at least 30 minutes of real video
   and non-silent audio. Keep the original `.ftproj` and all source media safe
   and separate. Confirm no other renderer is writing in the target folder.
3. Set up enough free disk space for two independent exports. Close other
   heavy applications and record GPU/Windows/Qt render backend, project FPS,
   encoder, expected output dimensions and the exact build SHA locally.
4. Install FFmpeg/FFprobe and Python separately for *independent verification*.
   The check script only reads test output; it does not upload footage.

## Repeated renderer exports using the existing local-only harness

From a PowerShell session in the FrameTrellis source checkout, adapt the
absolute paths below to your **copied** project and installed render helper:

```powershell
.\scripts\windows\Test-FrameTrellisRepeatedExports.ps1 `
  -Renderer "C:\FrameTrellis-trial\frametrellis-render.exe" `
  -Project "C:\FrameTrellis-QA\project-copy.ftproj" `
  -OutputDirectory "C:\FrameTrellis-QA\new-test-results" `
  -Fps "30000/1001" -Runs 2 -TimeoutSeconds 7200 `
  -SampleResources -SampleIntervalMs 500
```

The harness refuses an already-used run folder, never uploads logs and
creates `run-001/export.mp4`, `run-002/export.mp4` plus a local JSON summary.
It validates process exits and nonempty files, **not** actual MP4 decoding.
Inspect both output media independently before accepting either pass.
For another FPS setting, use a fresh, empty output directory and record
that distinct run. Preserve failure logs locally and redact any sharing.

## Independently validate the full MP4 streams

For a test where the **known expected** output is 1920x1080,
`30000/1001` FPS, exactly 1800 seconds and non-silent AAC:

```powershell
python .\packaging\verify_export_media.py `
  "C:\FrameTrellis-QA\new-test-results\run-001\export.mp4" `
  --fps 30000/1001 --width 1920 --height 1080 `
  --duration 1800 --decode-timeout-seconds 7200
```

Use your project's **real expected** output dimensions and duration, not
these sample values. Repeat for `run-002\export.mp4`. The verifier relies
on independent FFprobe metadata, full FFmpeg video/AAC decoding, exact
rational FPS and non-silent audio. The expanded timeout and maximum two-
second duration tolerance were integrated in
[PR #319](https://github.com/sanskarIN/frametrellis/pull/319).
The exact tested source must contain that merged verifier; future
decoded-picture checks in [PR #331](https://github.com/sanskarIN/frametrellis/pull/331)
must not be claimed until separately merged and qualified.
A failing decode, truncated duration, missing sound or wrong stream
properties blocks candidate acceptance.

## GUI / installer acceptance that scripts cannot establish

- Cold-launch installer and portable ZIP repeatedly with the **default GPU
  backend**; screenshot the main window and record failures.
- Preview real audio with actual speakers/headphones; seek/scrub, multi-track
  transitions and background editing while an export is active.
- Export from the GUI using match-project, 24, 25, 30000/1001, 30 and 60
  FPS, checking the same independently inspected output streams.
- Cancel early/late and retry. Check no stale partial output replaces a
  preexisting final MP4; verify user data and project state remain intact.
- Reopen a **backup** v1.5.0/v1.5.1 project and preserve the original; test
  save/close/reopen and autosave recovery.
- Record a clear go/no-go for the editor and render-helper native crash
  signatures [#175](https://github.com/sanskarIN/frametrellis/issues/175)
  and the intermittent Windows 11 ARM x64-emulation startup failure
  [#185](https://github.com/sanskarIN/frametrellis/issues/185).
  If crashes recur, preserve redacted timestamps, application logs, fault
  module and Windows Event Viewer evidence **locally**; never upload memory
  dumps or private footage by default.
