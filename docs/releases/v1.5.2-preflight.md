## 3. Required physical-device acceptance

Follow the [local-only Windows 30-minute export and audio QA worksheet](v1.5.2-physical-windows-qa.md),
recording actual hardware measurements and preserving source media backups.

- [ ] **Windows x64**: install and portable ZIP, cold and repeated launches,
  About version and source SHA, default GPU rendering, accurate picture,
  real preview audio (not dummy SDL/WASAPI).
- [ ] Import → edit → save → close → reopen and autosave recovery on
  **copies** of existing .ftproj projects from v1.5.0 and v1.5.1.
- [ ] Real multitrack **30+ minute H.264/AAC** export, source-to-final
  sound/picture sync, playable re-import, actual duration/resolution/codec
  checks, and repeated exports without unexpected process closure.
- [ ] Match, 24, 25, 30000/1001, 30 and 60 FPS selection during export,
  with correct retained project FPS and full-frame/range accuracy.
- [ ] Cancel before/after renderer startup, retry and overwrite protection,
  failure with missing source/disk pressure, preserving existing output
  and clearing only this job's temporary .part files.
- [ ] Review editor `0xC0000005` / renderer `0xC0000006` long-export
  native crashes ([#175](https://github.com/sanskarIN/frametrellis/issues/175)).
  No root-cause fix is established; record an evidence-based explicit go/no-go.
- [ ] **Windows ARM x64-emulated** independent default-GPU starts,
  software-rendering and diagnostic audio variations; review
  [#185](https://github.com/sanskarIN/frametrellis/issues/185) without
  claiming green hosted tests mean a permanent fix.

## 4. Five-file offline candidate (never automatic publication)

Only after the reviewed v1.5.2 version and release-notes PR merges:

1. Use the **[Prepare manual release workflow](https://github.com/sanskarIN/frametrellis/actions/workflows/release.yml)** on protected `main`.
   Require successful run with `head_sha` equal to the *frozen candidate*.
   The preparation workflow does not publish a tag or GitHub Release.
2. Download the unexpired `manual-release-assets` artifact from that
   exact run. Require five files in `release/` plus `release-notes.md`:
   `FrameTrellis-1.5.2-windows-x64-setup.exe`,
   `FrameTrellis-1.5.2-windows-x64.zip`,
   `FrameTrellis-1.5.2-windows-x64.spdx.json`,
   `FrameTrellis-1.5.2-windows-x64-third-party-sources.tar`, and
   `SHA256SUMS.txt`.
3. Verify:
   ```bash
   python3 packaging/verify_release_assets.py --version 1.5.2 --directory ./release
   (cd release && sha256sum --check SHA256SUMS.txt)
   ```
   Independently inspect version, source-provenance, ZIP/installer and
   corresponding-source/SBOM accuracy. These checks do not replace
   hardware audio and long-export tests.

## 5. Separate owner approval and public verification

- [ ] Obtain explicit owner permission for the *exact frozen SHA*,
  distribution scope and known unresolved risks **after** acceptance.
  CI, version metadata, this checklist and a release PR are not permission.
- [ ] Only on that permission, owner manually publishes tag `v1.5.2`
  pointing to the identical verified protected-main SHA; requires its
  distinct `FrameTrellis-1.5.2-SOURCE-BUILD-OWNER-APPROVED` marker.
  Never copy a v1.5.0/v1.5.1 marker.
- [ ] Owner-gated attachment must refuse pre-existing release files,
  a mismatched tag/SHA, unverified release notes, missing same-SHA CI,
  expired or duplicate artifacts, or incomplete checksum verification.
- [ ] Confirm exactly five public ready files, expected sizes and SHA-256
  digests on GitHub and working website download links **before** announcement.

**No release schedule or publication approval is implied. Linux/macOS are
source builds under the proposed five-file distribution; experimental
unnotarized DMGs/AppImages are not official release binaries.**
