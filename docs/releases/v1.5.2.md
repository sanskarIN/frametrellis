# FrameTrellis 1.5.2 — Maintenance Release

> CANDIDATE NOTES — NOT PUBLISHED. These are proposed changes after stable
> v1.5.1; the text must be reviewed, updated and this warning removed only
> when the exact v1.5.2 release candidate is frozen and qualified.

FrameTrellis is a local-first open-source video editor using C++20, Qt 6,
MLT and FFmpeg. This maintenance candidate concentrates on predictable MP4
export completion, exact rational/frame-rate calculations and safer timeline
input. It does **not** promise a solution to an unconfirmed native crash.

## Verified changes after v1.5.1 (merged to development main)

### MP4 export and renderer protocol

- Enforce the supported 1–240 FPS export range when matching an in-memory
  project's frame rate, not only when entering an explicit override
  ([#308](https://github.com/sanskarIN/frametrellis/pull/308)).
- Require a valid renderer **started** event before accepting completion
  ([#309](https://github.com/sanskarIN/frametrellis/pull/309)).
- Keep the export destination in sync while typing in the export dialog,
  even before focus leaves the text field
  ([#311](https://github.com/sanskarIN/frametrellis/pull/311)).
- Reject a zero-exit renderer's false success when its **started** frame
  count contradicts the expected frozen-project range. Do not replace the
  verified total with the child process's claim or accept incompatible
  progress; retain the previous output on protocol failure
  ([#313](https://github.com/sanskarIN/frametrellis/pull/313)).

### Exact timebase and timecode arithmetic

- Compare large rational values exactly on supported compilers rather than
  losing low-bit precision in a floating-point fallback
  ([#310](https://github.com/sanskarIN/frametrellis/pull/310)).
- Prevent false overflow when a frame-rate conversion has a very wide
  intermediate multiplication but a valid signed 64-bit result
  ([#312](https://github.com/sanskarIN/frametrellis/pull/312)).
- Reject a misplaced/repeated SMPTE drop-frame semicolon rather than silently
  interpreting a malformed timecode as a different valid time
  ([#314](https://github.com/sanskarIN/frametrellis/pull/314)).

### Test and build reliability

- Detect preview-loop restarts despite coalesced Qt GUI frame notifications,
  avoiding a false failure on heavily loaded macOS CI hosts
  ([#316](https://github.com/sanskarIN/frametrellis/pull/316)).

## Candidate change awaiting integration

The following is **not included in this candidate scope until merged and
verified on the eventual frozen main SHA**:

- [#315](https://github.com/sanskarIN/frametrellis/pull/315) — validate
  the exact requested output pathname rather than a trimmed variant.
  Its macOS native engine-fixture test failure must be resolved or
  independently verified before the code is included in release notes.

## Distribution scope under consideration

The existing v1.5.1 release has five official files: an **unsigned Windows
x64 installer**, a portable ZIP, SPDX 2.3 SBOM, corresponding third-party
source archive and SHA256SUMS.txt. The proposed v1.5.2 scope keeps this
Windows-binary plus **Linux/macOS source-build** model unless the owner
explicitly approves a genuinely verified different distribution.
Experimental AppImages and unnotarized macOS DMGs are **not** production
installers.

Back up important `.ftproj` projects before a future upgrade. Reopen copies
of v1.5.0/v1.5.1 projects in the candidate before declaring compatibility.

## Unresolved release risks

- The previously observed Windows x64 long-export editor/render failures
  ([#175](https://github.com/sanskarIN/frametrellis/issues/175))
  have **no confirmed native root-cause fix**. A passing synthetic export
  or protocol test does not certify a real 30-minute H.264/AAC job.
- The intermittent Windows 11 ARM x64-emulation GUI startup failure
  ([#185](https://github.com/sanskarIN/frametrellis/issues/185))
  remains under investigation; hosted CI non-reproduction is not resolution.
- Real Windows output hardware, long-duration export, FPS overrides,
  cancel/retry, output preservation, clean-machine startup and project
  compatibility require physical-device evidence.
- Hardware-accelerated export, proxy editing and embedded switchable MP4
  subtitle tracks remain outside this maintenance candidate.
