# FrameTrellis 1.5.3 — owner release runbook

**Preparation only.** Follow the [preflight](v1.5.3-preflight.md) and
[candidate notes](v1.5.3.md). Nothing here authorizes public release.
Target date: 26 November 2026. The prior published stable is
[v1.5.2](https://github.com/sanskarIN/frametrellis/releases/tag/v1.5.2).

## 1. Freeze one accepted main revision

Require merged PR #350 and the separately reviewed version/notes PR.
Check CMake reports 1.5.3, the notes no longer contain the candidate-only
preamble, and no approval marker is committed to the notes. Do not freeze
while another integration is pending. Record the 40-character main SHA.
Do not create a tag at this stage.

```bash
git fetch origin main --tags
git rev-parse origin/main
git show origin/main:CMakeLists.txt | head -n 12
git ls-remote --tags origin refs/tags/v1.5.3
```

The last command must have no output. An existing tag or release is a
stop condition; inspect it rather than changing it.

## 2. Qualify the exact revision

Verify completed/success push runs at the frozen SHA, not PR heads:

- [CI](https://github.com/sanskarIN/frametrellis/actions/workflows/ci.yml)
- [Linux and macOS desktops](https://github.com/sanskarIN/frametrellis/actions/workflows/desktop-platforms.yml)
- [Windows packages](https://github.com/sanskarIN/frametrellis/actions/workflows/package-windows.yml)
- [Website](https://github.com/sanskarIN/frametrellis/actions/workflows/website.yml)

Check the Windows clean-host verification jobs, native macOS ARM and Intel
tests, and Linux tests. Experimental AppImage/DMG packages are not official
installers and do not substitute for the required native desktop checks.

For local physical Windows QA, use same-SHA installer and portable ZIP,
record their About version and source revision, and follow the testing
procedure from the [previous physical QA worksheet](v1.5.2-physical-windows-qa.md)
with **1.5.3 candidate paths, version and measured expectations**, not
old binaries. Record two 30+ minute exports and independently decode them.
Test immediate cancel, cancellation while finalizing, retry, preservation of
existing outputs and unclaimed partials, audio sync, save/reopen and startup.
Do not claim a native crash is fixed based solely on hosted CI.

## 3. Assemble and inspect offline candidate

The [Prepare manual release](https://github.com/sanskarIN/frametrellis/actions/workflows/release.yml)
workflow is non-publishing. Use a successful run with the exact frozen
main SHA. Download its unexpired `manual-release-assets` artifact and
verify that it contains `release-notes.md` plus these five files:

| File | Purpose |
|---|---|
| FrameTrellis-1.5.3-windows-x64-setup.exe | Windows x64 installer |
| FrameTrellis-1.5.3-windows-x64.zip | Portable Windows application |
| FrameTrellis-1.5.3-windows-x64.spdx.json | SPDX software bill of materials |
| FrameTrellis-1.5.3-windows-x64-third-party-sources.tar | Corresponding third-party source |
| SHA256SUMS.txt | SHA-256 payload manifest |

From the frozen source checkout, verify extracted files:

```bash
python3 packaging/verify_release_assets.py --version 1.5.3 --directory ./release
(cd release && sha256sum --check SHA256SUMS.txt)
```

The installer is unsigned. Linux and macOS are source builds; no production
AppImage or notarized DMG is included. Reject mixed revisions, missing or
unexpected assets, and checksum mismatches.

## 4. Owner decision and publication

Record actual test outcomes, artifact run ID and frozen SHA. Request a
separate explicit owner go/no-go for that revision. No development request,
calendar target, green PR or offline artifact is an approval.

Only following approval, use [GitHub New Release](https://github.com/sanskarIN/frametrellis/releases/new)
with tag v1.5.3, the frozen SHA, title **FrameTrellis 1.5.3 — Maintenance Release**,
and the verified assembled notes. Leave the prerelease option unchecked.
Use the separate exact source-build approval line required by the
[version-specific uploader](https://github.com/sanskarIN/frametrellis/actions/workflows/release-assets-v153-source.yml).
Leave attachments empty if using that uploader. Do not publish without the
prior offline candidate.

Check uploader success, the public five-file inventory, byte sizes and
hashes. Verify the website download links before announcing the release.
A failed upload means the public page is incomplete; do not overwrite prior
assets or retag a release.
