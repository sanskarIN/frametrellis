# FrameTrellis 1.5.4 — Maintenance Release

This maintenance version focuses on protecting saved projects, safely sizing
native previews, validating the media thumbnail cache, and preserving recovery backups.

## Improvements and fixes

- Validate serialized media probe fields and enforce the project document
  size limit before replacing an existing project file ([#342](https://github.com/sanskarIN/frametrellis/pull/342)).
- Refuse nonregular project inputs and surface file read errors.
- Bound native preview dimensions using integer scaling even when a display
  limit is omitted; respect small and odd bounds ([#345](https://github.com/sanskarIN/frametrellis/pull/345)).
- Reject invalid thumbnail requests and inspect cached PNG dimensions before
  decoding; regenerate corrupt cache entries without following cache symlinks
  ([#343](https://github.com/sanskarIN/frametrellis/pull/343)).
- Preserve renamed recovery backups when either the replacement project or
  its metadata cannot be committed; retain the original project path on
  later autosaves and reject invalid recovery candidates
  ([#344](https://github.com/sanskarIN/frametrellis/pull/344)).
- Add unit, integration and GUI regressions for these reliability improvements.

## Distribution and limitations

Proposed distribution: unsigned Windows x64 installer and portable ZIP,
SPDX SBOM, corresponding third-party source archive and SHA256SUMS.txt.
Linux and macOS remain source builds. The larger timeline review, checkpoint
and portable project features are outside the maintenance scope.
Physical long-export and Windows ARM startup qualification remains necessary;
hosted tests alone cannot establish these outcomes.

See [qualification checklist](v1.5.4-preflight.md).
