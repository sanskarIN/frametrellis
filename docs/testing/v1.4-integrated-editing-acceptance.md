# FrameTrellis v1.4 integrated editing acceptance

This is a **manual release acceptance checklist**, not a record of completed
manual tests. The latest published stable is **v1.3.1**; v1.4 editing features
on `main` are not automatically part of that stable release. Record the build
commit SHA, OS, build/package origin, test media and evidence for every run.

## Build and fixture prerequisites

- [ ] Build and run the same verified `main` commit with the documented Linux
  CMake preset and Windows MSYS2 package workflow.
- [ ] Record CI links for GCC warnings-as-errors, unit/GUI, ASan+UBSan, Windows
  packaging, website, and renderer container on that **exact commit**.
- [ ] Create a **new, disposable** 30 fps project. Use two video tracks and one
  audio track. Include a 10-frame video clip, a 120-frame video clip, two
  separated clips on the second video track, and a 90-frame audio clip.
- [ ] Include a video with sound, a still PNG with alpha, and a source with
  known high/low audio levels. Keep all original media outside the project.
- [ ] Add two review markers, a subtitle cue, an opacity keyframe curve and
  an audio-volume keyframe envelope. Save a baseline project copy.
- [ ] Ensure **Undo** and **Redo** are both available, and note the
  current project-format version before editing.

## Timeline safety and precision

| ID | Manual action | Required result |
|---|---|---|
| T01 | Select a video and audio clip on different tracks; nudge the group 10 frames right | Both move 10 frames; relative offsets, sources, effects and trims unchanged; one Undo restores both |
| T02 | Align the earliest selected start to an empty playhead position | Earliest start equals playhead; all selected clips keep relative spacing; one Undo |
| T03 | Align the selected range's latest **exclusive end** to playhead | Entire group shifts together; exact half-open boundary semantics; one Undo |
| T04 | Move selection left so one clip would start before frame zero | Refused; no partial clip movement and no new Undo entry |
| T05 | Move a selected group so one clip collides with an unselected clip | Refused atomically with the original timeline retained |
| T06 | Lock one selected track, then retry a multi-track alignment | Refused; no changes to any other track |
| T07 | Insert a custom 37-frame gap at an empty edit boundary | Following clips move exactly 37 frames with source trims intact; one Undo |
| T08 | Remove the same empty 37 frames | Original clip positions restored; source media not changed |
| T09 | Position playhead inside a clip and choose remove-empty-time | Refused; existing footage never deleted |
| T10 | Close gap to next clip across video/audio tracks | Uses closest later clip across all tracks, never only the active track |
| T11 | Select several clips; navigate to selection start and last visible frame | Playback seeks to exact first and last visible frames; project and Undo state unchanged |
| T12 | Trim one selected clip to playhead, then Undo/Redo | Source in/out and sequence range update correctly; other clips and audio remain untouched |

## Batch properties and output parity

| ID | Manual action | Required result |
|---|---|---|
| B01 | Apply 10-frame fade-in to long and 10-frame clips together | Each gets a valid fade length; opposing fades do not overlap |
| B02 | Apply an approximately one-second fade-out to unequal-length clips | Each value clamps to its own remaining duration; one Undo restores every clip |
| B03 | Clear selected fade-ins, then Undo | Prior fade-ins return with all other attributes unchanged |
| B04 | Change selected video/audio gain to 50%, then 150% | Only base gain changes; mute, automation curves, transforms and fades preserved; one Undo each |
| B05 | Set selected video clips to 50% opacity | Base opacity changes without deleting keyframes or source alpha; audio clips excluded |
| B06 | Mix an audio-track clip into a video opacity/picture-adjustment selection | Entire command rejected without editing video or audio |
| B07 | Apply brightness, contrast and saturation presets to multiple video clips | Only the chosen property changes; independent properties, fades and keyframes preserved |
| B08 | Repeat a preset already applied to every selected clip | No-op rejected; no redundant Undo history entry |
| B09 | Lock one selected clip's track and try any batch property edit | Entire batch rejected atomically |
| B10 | Export a short H.264/AAC MP4 of layers, fades and audio after applying edits | Encoded output matches expected opacity/fade layers and audible gain; no extra or missing frames |
| B11 | Save, close, reopen, and export the edited project | Properties, automation, media links, markers, subtitles and frame placements remain intact |

For B10, inspect rendered frames at the beginning, midpoint and end of a
fade rather than judging only the preview. Do not claim waveform/audio output
parity without listening or comparing decoded audio with the baseline.

## Project format and recovery

- [ ] Open a copy of a **v1 project** in the current editor, check media links,
  save to a new filename, close and reopen. Do not overwrite the original.
- [ ] Repeat with representative v2–v6 projects that exercise markers, volume
  keyframes, opacity curves, transform curves, and subtitle content.
- [ ] Open a **copy** of a v1.4-saved file with the v1.3.1 reader and verify
  unsupported newer formats are **refused safely**, rather than silently
  discarded. Only expect refusal for projects that actually require a newer
  format; basic projects may still save to older compatible formats.
- [ ] Simulate missing media, relink to its original file, then verify playback
  and export. Ensure no operation overwrote original source media.
- [ ] Verify autosave/crash recovery from a disposable unsaved project copy,
  including preserving edit history where documented.
- [ ] Confirm the project's backup copy still opens after all negative tests.

## Packaging, interoperability and release decision

- [ ] Verify both Windows installer and portable ZIP on independent clean
  Windows environments, including the existing Windows 11 ARM64 x64-emulation
  smoke-test gate, retaining screenshots and logs.
- [ ] Perform one actual-GPU monitor/playback check on supported desktop
  hardware, since the automated GUI uses a software Qt backend.
- [ ] Import the generated CMX3600 EDL into at least one third-party NLE and
  compare timecodes. Check WebVTT chapters, SRT and CSV audit exports in their
  intended consuming applications.
- [ ] Compare short and longer timeline performance; look for UI stalls,
  high memory use, stutter, thumbnail corruption or audio glitches.
- [ ] Run a full **import → edit → save → reopen → preview → export** journey
  with actual editor controls, not only headless scripts.
- [ ] Inspect the portable archive, installer version, bundled notices, license,
  source code, SBOM and SHA-256 files. Verify package version/tag consistency.
- [ ] Only consider a v1.4 prerelease after checks above have recorded evidence,
  latest integrated `main` CI is green and a separate release decision is made.

**Record evidence:** commit SHA; OS, CPU/GPU and Qt backend; test case ID;
pass/fail/blocked; observed versus expected result; screenshot or media sample
location; log/Actions URL; and an owner for unresolved issues.

Automated tests already cover many unit, GUI and rendering invariants, but
**none of the unchecked manual rows above are asserted complete** by this
document. Do not upgrade a pending manual row to passed solely because CI is green.
