# Portable project bundles (development)

Use **File → Portable Project Bundle…** to create an independent, editable copy
of the current project, including the source media. This is not a video export,
a ZIP archive, or a copy of the editor itself.

## Create a bundle

1. Choose an existing parent folder on a drive with sufficient free space.
2. Enter a new folder name (1–80 ASCII letters, digits, hyphens or underscores).
3. Choose whether to include all imported sources or only sources used on the timeline.
4. Click **Create portable project**. Progress shows copied bytes and media counts.
5. When complete, open `project.ftproj` inside the new folder using FrameTrellis.

The copy receives a new project identity. Clips, tracks, transitions, markers,
subtitles, keyframes, settings and display names are retained. It reflects the
in-memory editing state when creation starts, including unsaved changes. The
original project, source media and undo history are not modified.

Used-only mode removes unused media references from the copy only. Missing or
changed included sources stop creation; relink or restore them first. Missing
unused sources do not prevent used-only creation.

The operation copies bytes rather than decoding or re-encoding media. A large
bundle can occupy as much storage as all included source files. The worker
checks available space where possible, but later writes can still fail if the
disk fills. Copying can be cancelled; cancellation is checked between chunks
and before publication, although a slow filesystem read may delay a response.

Close the dialog with **Hide** to continue editing while the copy runs. Reopen
it from the File menu to see progress and results. Finish or cancel before
quitting FrameTrellis.

## Move and edit

A bundle folder contains:

- `project.ftproj` — an ordinary editable project document.
- `media/` — copied source files with unique generated names.
- `manifest.json` — original file sizes and SHA-256 checksums.

Keep the folder together when copying it to another drive or computer. Its
project prefers contained, project-relative media paths, and the preference is
retained on later saves. Use a FrameTrellis build with portable-bundle support.
An earlier reader may ignore the relative-path preference.

Newly imported or relinked files outside the bundle remain external references.
Create a new bundle to include those sources in an independent copy. The
original manifest is not regenerated by saving edits.

## Verify a bundle

Open the same dialog, select **Verify bundle**, browse to the bundle folder and
choose **Verify recorded files**. The worker reads and checks each recorded file
against its original size and SHA-256. The result distinguishes a modified
project document from missing or changed copied media.

Saving an edit changes the project checksum, which is expected. Verification
checks the original manifest's media, not newly imported files or unused extra
files added later. If the project still matches its original checksum, the
verifier also checks that the manifest lists the same media identities and paths.

Checksums detect accidental changes; they are not digital signatures and do
not prove authenticity. A valid bundle is not a guarantee that every media
codec will decode on another machine. Keep separate backups and inspect the
actual exported video as well.

## Failure and privacy

The operation stages files in a temporary sibling directory and publishes the
completed folder only after writing the project and manifest. Existing
destination folders are refused. A normal failed or cancelled operation cleans
up its temporary folder; an abrupt process or power failure can leave an
incomplete hidden `.ft-bundle-*` directory, which may be removed after confirming
no copy is running.

The bundle contains your original media bytes and editable content, including
caption text and names. The generated project and manifest omit original
absolute source paths for included assets. Review content before sharing.
